# P2-7 结构化长期记忆实施记录

## 目标

解决长期记忆只保存“用户问题 + 助手回答原文”的问题，同时保留原始问答作为可导出、可删除的审计证据。默认注入模型上下文的内容改为由用户明确表达提取出的结构化记忆。

本阶段参考了 [SimpleMem 论文（arXiv:2601.02553）](https://arxiv.org/abs/2601.02553) 和其 [GitHub 开源实现](https://github.com/aiming-lab/SimpleMem) 的相关设计思想。项目仍保持 FastAPI + LangGraph + Grill Engine + SQLite/PostgreSQL + FAISS 的小型平台架构，不引入独立记忆服务、消息队列、多模态记忆或精确 Tokenizer。

## 参考来源与借鉴边界

本项目参考的是论文和开源项目中的方法论，不是对 SimpleMem 的代码复制或完整复现，具体借鉴点如下：

| SimpleMem 参考思想 | 本项目的落地方式 |
|---|---|
| 语义结构化压缩：把长期对话从原始文本转化为更紧凑、可操作的记忆单元 | 新增 `memory_items` 结构化记忆层，将用户表达提取为 `memory_type`、`memory_key`、`memory_value`、置信度、敏感级别和来源信息；原始问答仅作为审计证据保留 |
| 在线记忆构建与增量合并：新信息到达时去重、合并和处理冲突 | 使用内容哈希去重；集合字段合并不同值；标量目标或偏好发生变化时保留旧记录并标记为 `superseded` |
| 按当前任务或意图检索记忆：避免把全部历史内容无差别注入上下文 | 根据 `meal_planner`、`calorie_query`、`advice` 等当前任务筛选可召回字段，并限制召回数量；`proposed`、`rejected` 和过期记忆不进入默认上下文 |

同时保留本项目自身的边界设计：只从用户消息提取事实，不从助手回答反推；高敏感记忆默认需要用户确认；记忆受租户、用户授权和删除接口约束；默认采用确定性提取，未接入 SimpleMem 的完整模型流水线或评测结论。

## 实际实现

### 1. 配置与数据模型

- 增加结构化记忆开关、候选数量、召回数量、低风险自动确认和默认 TTL 配置。
- 新增 `memory_items` 表和 Alembic 迁移 `0013_structured_memory`。
- 记忆条目保存类型、字段、JSON 值、状态、置信度、敏感级别、来源会话、来源摘录、有效期、冲突链和内容哈希。
- 状态包括 `proposed`、`active`、`rejected`、`superseded`、`expired`。

### 2. 确定性记忆提取

新增 `core/memory_extractor.py`，只读取用户消息，不从助手回答推断事实。当前覆盖：

- 过敏或不耐受；
- 忌口和不喜欢的食物；
- 饮食偏好；
- 健康目标；
- 热量记录偏好；
- 可用烹饪设备；
- 活动习惯和每天用餐次数。

过敏、健康目标等高敏感条目默认进入待确认状态；普通且明确的偏好在配置开启时自动进入启用状态。临时表达会记录短期过期时间。

### 3. 在线合并与冲突处理

新增 `core/memory_merge.py`：

- 通过标准化值和 SHA-256 内容哈希去重；
- 集合型字段合并不同表达的值，重复值去重，并将被合并的旧条目标记为 `superseded`；
- 标量目标或偏好出现新表达时，将旧条目标记为 `superseded`，保留来源和变更链；
- 通过 `source_conversation_id` 和 `source_excerpt` 支持追溯；
- 删除或撤销记忆同样删除结构化条目。

### 4. 工作流接入

- 最终回答继续保存原始问答作为审计证据；追问、澄清和确认阶段也会从用户消息提取事实，但不会把助手追问或建议写成用户记忆。
- `retrieve_memory` 节点传入当前任务、操作和请求意图。
- 餐食规划优先召回过敏、忌口、饮食偏好、设备和健康目标；热量查询优先召回目标、热量记录偏好和饮食偏好；普通建议优先召回目标、活动量和长期偏好。
- 原始问答不再作为默认长期记忆注入 Prompt；召回内容继续以“不可信历史记忆”处理，不能覆盖当前用户表达或 Grill 状态。

### 5. API 与前端

新增接口：

- `GET /memory/items`
- `POST /memory/items/{id}/confirm`
- `POST /memory/items/{id}/reject`
- `PATCH /memory/items/{id}`
- `DELETE /memory/items/{id}`

接口均通过当前用户和当前租户校验。个人档案页增加待确认、已启用记忆的展示、确认、拒绝和删除操作。

## 验证记录

- 结构化记忆专项测试：9 项通过，覆盖追问阶段提取和集合字段合并。
- Ruff：通过。
- Alembic 空 SQLite 数据库已从初始版本连续升级到 `0013_structured_memory`。
- 前端生产构建：通过（TypeScript 检查、Vite 打包均通过）。

## 已知边界

- 目前默认使用确定性规则提取，`MEMORY_EXTRACTION_LLM_ENABLED` 保留为后续可选增强开关，避免同步模型调用拖慢对话。
- 结构化记忆不会自动改写正式健康档案，用户需要通过资料建议或档案页显式确认。
- 精确 Token 计数按既定决策忽略；长期记忆与 P2-6 上下文治理是两个独立层次。
